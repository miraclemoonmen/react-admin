# PROJECT_RULES.md

## 目的

本文件是 `WinRide-Console` 管理端前端项目的长期工程规则来源，用于约束 AI 协作、后台壳体、页面结构、接口接入、权限和交付门槛。

## 项目定位

`WinRide-Console` 是 WinRide 的管理后台前端。项目当前适合按后台管理系统重新建设，但必须围绕真实后端接口和权限模型推进，不做脱离契约的演示型页面。

## 文档职责

- `README.md`：项目入口、常用命令和文档地图
- `AGENTS.md`：AI 现场协作规则
- `docs/PROJECT_RULES.md`：长期工程规则
- `docs/COLLAB_RULES.md`：协作、外部材料和跨仓库口径
- `docs/WORKING_LOG.md`：当前状态摘要、关键决定和活跃需求索引
- `docs/req/*.md`：单需求记录、实现过程、验证结果和遗留问题

## 任务流程

实现类任务默认按以下顺序执行：

1. 明确目标、范围和非范围
2. 查阅项目文档、后端接口和相关代码
3. 判断风险等级
4. 说明准备步骤并获得确认
5. 初始化或更新需求记录
6. 小步实现
7. 执行必要校验和运行态验证
8. 更新需求记录和状态摘要

## 风险分级

- 轻流程：文案、局部样式、单文件小修复
- 标准流程：新增列表页、表单页、接口接入、模块内组件拆分
- 重流程：登录认证、权限、菜单、路由主干、请求封装、全局状态、后台壳体

## 工程规则

- 路由入口优先保持装配职责，复杂查询、表格、抽屉和表单拆到模块内组件
- 正式接口访问应集中到明确的 api/service 层，不在页面散落裸请求
- 后台页面默认具备加载态、空态、错误态、提交态和失败反馈
- 管理后台默认优先使用“查询区 + 结果区”结构承载列表类页面
- 查询类页面默认保留查询按钮和重置按钮，不让筛选项变化直接触发请求
- 表格类页面默认考虑分页、稳定行 key、危险操作确认和权限控制
- 新增、编辑、审核、授权等复杂操作优先使用抽屉或弹窗组件，不长期内联在页面入口
- 公共能力只有在多个页面真实复用后再提升到公共层

## 权限与认证规则

- 认证、登录失效、401/403 分流、菜单权限和按钮权限属于高风险链路
- 菜单展示、路由访问和操作按钮应使用统一权限来源
- 当前用户无权限的操作默认隐藏或禁用，并给出可理解反馈
- 不在页面内各自遍历权限结构实现一套临时判断

## 接口接入规则

- 后端接口以 `WinRide-API` 为准
- 接入前确认路径、方法、请求参数、响应结构、分页结构、错误码和权限要求
- 接口文档不明确时，先记录疑点并确认，不把猜测写成长期实现
- 用户态文案优先中文，不直接暴露后端原始异常、英文底层错误或堆栈

## 质量门槛

交付前默认至少执行：

```bash
npm run typecheck
npm run build
```

涉及页面行为、表单、表格、权限和路由时，默认补充浏览器运行态验证。

如果无法执行完整校验，必须说明原因和未覆盖风险。

## Git 规则

- 提交信息默认使用中文，格式为 `类型: 描述`
- 提交前确认暂存范围，避免提交本地环境文件、调试改动和无关格式化
- 不擅自创建、切换或推送分支

## 记录要求

- 写入类任务默认需要记录到 `docs/req/*.md`
- 新增需求记录时同步更新 `docs/req/INDEX.md`
- 当前主线、阻塞项和重要活跃需求同步到 `docs/WORKING_LOG.md`
- 记录必须写清目标、范围、非范围、接口影响、实际改动、验证结果和遗留问题
